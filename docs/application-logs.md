# 启动器运行日志

设置 → 关于 Nixel → 启动器日志可打开本地日志目录。插件 Host 故障恢复页保留同一入口，Host 无法启动时仍可使用。

主进程的 `ApplicationLog` 保存 `<应用数据目录>/logs/launcher.jsonl`。单文件上限 2 MiB，超过时轮换为 `launcher.previous.jsonl`，最多保留两个文件。日志在启动间追加，每条 JSON 记录包含 UTC 时间、稳定事件名和对应标识或状态。

记录范围：应用启动/退出请求，Host 创建、就绪和退出码，插件状态/版本变化，任务状态变化，游戏进程进入/离开运行列表，命令与系统操作失败，以及渲染进程退出和页面加载错误码。快照比较只在状态变化时写入，不随下载进度重复记录；首次载入不会把历史完成任务记成新事件。

记录器接收明确的事件与元数据，不采集命令参数、插件配置、账号信息、任务消息、完整错误对象、URL 或控制台输出。业务错误细节继续使用任务中心与实例诊断报告。低频事件采用同步追加，使进程异常时已经记录的条目保留在磁盘。存储失败不阻止启动或游戏；打开日志目录时会报告当前写入错误。

任务错误保留原错误消息及聚合错误前 3 项的消息，并从错误、`cause` 链和聚合子错误提取技术错误码，例如 `fetch failed (UND_ERR_CONNECT_TIMEOUT)`。提取只接受 2–64 字符的大写字母、数字和下划线，最多遍历 32 个节点、8 层；错误码去重，原消息已有的码不重复追加。不会因此展开 `cause.message`、堆栈、URL、请求头或凭据。Host 任务服务继续将这一结果保存并显示在任务中心；这不扩展 `launcher.jsonl` 的事件字段，也不改变下载、超时或重试策略。

日志属于主进程系统能力：Host 尚未就绪或已经退出时仍需要记录。默认界面通过已有 IPC 来源校验调用 `NixelBridge.openApplicationLogs()`，不接受调用方指定日志路径，也不暴露通用写日志接口。Cordis 业务插件的状态由快照观察器记录，业务代码不依赖文件日志实现。

隔离操作核对了轮换、两次启动追加、重复快照去重、历史任务跳过、含敏感字段的快照不进入日志，以及写入失败通过入口报告。实际 Electron 中英文设置和故障恢复页已核对；主动结束自有 Host 后，日志保留异常退出码，恢复页可打开日志目录。
