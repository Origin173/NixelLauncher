# 切换游戏版本时联动更新内容

版本切换由实例插件负责；资源版本与必需依赖仍由各资源提供者解析。默认界面分为目标版本、逐项内容选择、最终文件确认三步。

- `instances.planVersionChange` 校验精确 Minecraft / 加载器版本，扫描内容，返回每项兼容版本及当前文件指纹。
- 用户为每项选择保留、禁用或精确版本更新。本地文件或兼容性未知的启用项必须选择；不会自动删除。已禁用内容更新后仍禁用。
- `instances.planVersionContent` 启动可取消任务，返回 `taskId` 与 `planId`；任务完成后通过 `instances.versionContentPlan` 读取最终文件清单。每个来源的所有更新根统一调用公开 `ResourceProvider.planInstall`，复用 `resource-dependencies` 的依赖解析、固定版本、去重与冲突检查。保留内容参与冲突检查；禁用项不视为启用冲突，但不能满足启用内容的必需依赖。
- 提供者必须返回与来源匹配的固定项目、版本、文件、URL 和校验值。下载信息只保存在 Host 缓存；界面得到公开文件信息。未实现 `planInstall` 的提供者仍可保留或禁用其内容，尝试更新会明确报错。
- `instances.changeVersion` 使用最终 `contentPlanId`、指纹和目标，不重新选择最新版本。确认风险后创建 `version-change` 自动备份，暂存内容及依赖，安装目标游戏文件，再次核对实际内容 SHA256、启用状态、游戏/加载器版本及实例提供者配置。
- 文件提交使用与整合包升级共同使用的 `file-transaction`：先持久化不可启动的错误状态及备份恢复提示，再保留原始文件并逐项写入。目标游戏/加载器/启动版本与内容记录最后在一次状态更新中提交。取消或失败恢复文件与原状态；回滚失败保留错误状态。进程中断后也不会把旧版本配置与部分新内容当作可启动实例。

暂存失败不改现有内容；游戏安装可能留下未使用的版本文件，可重试。配置和存档不参与内容写入，升级前的完整备份可以恢复为独立实例。成功提交后回滚缓存清理失败仅写任务日志，不把成功升级报告为失败。

路径检查拒绝实例文件路径越界及符号链接；同一目的文件、已存在但不属于待替换项目的文件、禁用目标重名均报冲突，不覆盖其他本地内容。实际文件发生变化时需重新预览。

此功能遵守资源提供者声明的兼容版本与依赖关系；跨来源项目不会推断为同一个模组，也不解析模组字节码推断兼容性。用户显式保留的未知/不兼容启用内容仍可能导致游戏加载失败，最终确认会单独列出。

已在独立数据目录验证真实文件 SHA256、ZIP 备份、文件提交与取消回滚，两来源依赖合并、版本冲突、禁用状态与固定计划重试均通过。中英文界面完成选择、确认与应用；这些异常和双来源场景使用隔离提供者。

2026-11-04 的在线组合使用正式 Minecraft 与 Modrinth 提供者：Minecraft 保持 1.21.1，Fabric 0.19.5 → 0.20.1，同时明确选择将 Sodium 0.8.12（`KIRFiWG4`）更新为 0.8.13（`SMxNOGZ6`）。最终文件计划固定准确来源和版本；应用后新文件 SHA-512 与官方清单一致，旧文件移除，原禁用状态与自定义配置保留。`version-change` 备份归档内的旧禁用文件匹配原版官方哈希，并保留原配置。

随后显式启用新 Sodium，用离线角色启动更新后的实例，确认 Fabric、模组、音频与纹理初始化，游戏正常退出码 0。Electron 和 Host 也正常退出。操作复用复制到独立目录的官方游戏/Java 缓存，新增模组与加载器文件下载共 6,688,262 字节，元数据另计；证据在本地忽略目录 `output/version-online-review/`。该组合保持 Minecraft 版本，跨 Minecraft 版本与线上 CurseForge 组合仍需按目标版本验证。
