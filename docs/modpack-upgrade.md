# 整合包整体升级

新导入的 Modrinth 与 CurseForge 整合包在 `Instance.modpack` 保存格式、包名、版本、原始清单及每个包文件的 SHA-256。通过资源页安装时还保存来源提供者 ID、项目 ID 与精确版本 ID。普通实例、旧版本导入但没有基线的实例不推断整合包身份；需要重新导入为新实例。

在实例概览选择“升级整合包”，选择来源版本或本地同格式文件。来源版本查询不限制当前 Minecraft 版本，因此新版可以携带不同的游戏和加载器版本。选择本地文件后，新的来源身份留空，避免把本地包误标为某个在线版本；仍可继续从本地文件升级。

## 比较规则

准备任务先在 Host 缓存中下载并解压新版，不修改原实例。比较旧包基线、当前文件、新包指纹：

- 原包文件未被用户更改：采用新版新增、替换或移除。
- 新旧包内容相同：保留当前本地状态，包括本地修改和删除。
- 本地内容偏离原包、新包也有变化：列为冲突，用户逐项选择保留或采用新版。
- `config/`、`defaultconfigs/`、`options*.txt` 和 `servers.dat` 已存在且新版不同：要求明确选择。
- `saves/` 和 `screenshots/` 始终保留；本地新增且不与新包路径冲突的文件保持原样。
- 同路径存在 `.disabled` 副本时提示用户，默认不替用户启用。跨文件名的模组更名按移除与新增分别展示，不猜测两个文件属于同一项目，用户可对每一项选择保留。

预览列出目标 Minecraft/加载器版本。应用时重新比较文件和实例设置、校验缓存文件的 SHA-256，变化后要求重新预览。路径经过目录边界检查，归档和目标路径不允许符号链接，重复大小写路径拒绝处理，`client-overrides` 对相同路径的优先级高于 `overrides`。

## 提交与恢复

应用由 Host 长任务执行，与实例其他任务互斥。先创建完整备份，再安装目标游戏组件，随后提交包文件。已修改文件在缓存中留有回滚副本；正常取消或异常会还原这些文件，成功后才提交整合包基线和游戏版本。新备份标记为整合包升级前的自动备份，与更换版本前的自动备份共用保留数量策略；手动备份不受影响。可从现有备份页恢复为新实例。

文件提交前把实例标为错误并写入备份恢复提示，成功或完整回滚后才恢复状态。因此 Host/系统在文件提交中途退出不会把混合状态标成可启动；重新打开后应先从提示中的备份恢复。无需假定进程退出时能执行清理。若回滚本身失败，错误包含备份 ID。

升级准备和应用都可取消、手动重试；应用重试仍使用原预览 ID、指纹与明确冲突选择。缓存被清理、实例文件改变或原预览不可用时，重新比较，不自动选择另一个版本。

## 模块与命令

`plugins/modpacks/` 的 `archive.ts` 解析清单，`materialize.ts` 暂存文件和捕获基线，`diff.ts` 比较并检查路径，`prepare.ts` 保存预览，`apply.ts` 编排备份、游戏安装、文件提交和回滚，`import.ts`/`export.ts` 处理原有导入导出。`commands.ts` 注册升级命令，入口复用实例管理已有的备份仓库。

| 命令                      | 输入                                                   | 返回                 |
| ------------------------- | ------------------------------------------------------ | -------------------- |
| `modpacks.versions`       | `{ id }`                                               | `ResourceVersion[]`  |
| `modpacks.prepareUpgrade` | `{ id, path? , versionId? }`，本地路径与来源版本二选一 | `{ taskId, planId }` |
| `modpacks.upgradePlan`    | `{ planId }`，准备任务完成后调用                       | `ModpackUpgradePlan` |
| `modpacks.upgrade`        | `{ id, planId, fingerprint, choices }`                 | `{ taskId }`         |

`choices` 使用包内相对路径作为键，值为 `keep` 或 `replace`。冲突必须有明确值，普通新增、替换和移除允许改为保留。保存使用共享 `modpack-contracts.ts`，没有新增 Host 业务服务。资源提供者通过可选 `downloadModpack` 返回经来源规则校验的归档；CurseForge 提供者通过 `resolvePackFiles` 返回清单指定文件的公开下载描述，整合包管理不导入来源内部实现。

## 设计参考与验证边界

阅读了 Prism Launcher 的 [ModrinthInstanceCreationTask.cpp](https://github.com/PrismLauncher/PrismLauncher/blob/develop/launcher/modplatform/modrinth/ModrinthInstanceCreationTask.cpp)：它保留旧清单并使用暂存目录，按旧清单处理移除文件，其源码对 override 和禁用模组保留也记录了待改进项。本实现只借鉴清单与暂存的设计，采用独立 SHA-256 三方比较和明确冲突选择，没有复制其实现或引入 XMCL。

本地操作验证使用独立数据目录及生成的两种格式归档，检查导入基线、差异、用户配置/存档保留、文件移除、正常取消回滚、重试提交和备份。游戏安装和来源下载使用 fixture，不能据此推断真实游戏启动、CurseForge 授权下载或所有第三方整合包均已验证。

独立 Electron 实例还验证了正常版本选择、Host 准备任务、英文冲突预览、未决冲突禁用提交、中文切换、确认升级及成功版本显示；真实 ZIP 文件和备份由现有实现处理，临时可信提供者仅提供本地归档和模拟游戏安装。原生选包对话框能打开，自动输入受窗口工具限制；这部分未将原生选取完成算作通过。
